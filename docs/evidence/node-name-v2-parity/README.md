# Go and Rust reference runners of the node-name verdict (version 2)

Part of the implementation of D1 (cic-primitives #39). Reference validation only: this is **not** a Forms integration. The gate `proposals/atom-grammar/check_name_vectors.py` (check C8) builds and runs both runners on **every run**.

* `go/` (standard library only, `go 1.21`) and `rust/` (the `regex` and `serde_json` crates, `Cargo.lock` committed, built with `--locked`): each **applies the rule it is given** to the names it is given and prints `id|accept` or `id|refuse`. They hard-code no pattern; they refuse to run with an empty rule or no names (exit 2).
* **The inputs are generated at run time from the current files**: `names.json` from `proposals/atom-grammar/name-vectors/node-name.yaml`, `rule.json` from the `name` sub-schema of `proposals/atom-grammar/instance-grammar.schema.yaml` (`minLength`, `pattern`, and the pattern of `not`). Nothing recorded is trusted: no input and no output is committed. `python3 proposals/atom-grammar/check_name_vectors.py --export DIR` writes both for a manual run.
* **What the gate checks** (C8): the fresh output of each runner has the exact inventory (every vector once; a duplicate, an unknown id, a malformed line, a verdict other than accept/refuse, a missing vector is refused), equals the `v2` column of the vector file, and equals the other runner's. A runner that fails to build or run is a failure. Without a Go or a Rust toolchain C8 is `NOT RUN`, and with `CIC_REQUIRE_NAME_RUNNERS=1` (set in the CI gate) it is a failure, never a skip. `CIC_NAME_GO` and `CIC_NAME_CARGO` name the commands (a container wrapper was used locally).
* **Seeded implementation faults** (`--self-test`, all red, each in C8 and with the expected message): a Go runner and a Rust runner that accept every name (the counterexample of the review of #41), that drop the start anchor of the rule they are given, a Go runner that hard-codes the V1 pattern, one that reads the wrong file, a Rust runner that prints nothing, a Rust runner that repeats a line. Before the fix, the same counterexample passed the gate (`../node-name-grammar-v2/red-f1-counterexample.txt`).
* **An equivalent mutant, found and not hidden:** removing the line-feed guard (`not`) from a runner changes **no verdict**: Go's RE2 and Rust's `regex` match `$` only at the end of the text, so `abc\n` is refused by the pattern alone. The guard is needed in **Python** (whose `$` also matches before a final line feed), and there it is proved by the vectors (`abc\n`, check C2). A seeded fault for it in the Go and Rust runners would be an equivalent mutant, so none is claimed; the first attempt at one was red only because the Go build failed on an unused variable, and was replaced.
* The faulted copies of the tree get fresh file modification times (cargo decides by mtime; a preserved old time reused the binary of an earlier faulted copy, which made a later fault run red for a stale binary: found and fixed).
