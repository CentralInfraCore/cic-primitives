# Go and Rust parity of the node-name verdict (version 2): the evidence

Part of the implementation of D1 (cic-primitives #39). The gate `proposals/atom-grammar/check_name_vectors.py` (check C8) reads these files.

* `names.json` and `rule.json` are **exported from the real files** (`export_inputs.py <dir>`): the names and ids from `proposals/atom-grammar/name-vectors/node-name.yaml`, the rule from the `name` sub-schema of `proposals/atom-grammar/instance-grammar.schema.yaml` (`minLength`, `pattern`, and the pattern of `not`). The gate recomputes both and refuses a difference, so the runners cannot be given a rule other than the grammar file's.
* `runner.go.txt` (standard library only) and `runner.rs.txt` (the `regex` and `serde_json` crates) **apply the rule they are given** to the names they are given and print `id|accept` or `id|refuse`; they hard-code no pattern. Both refuse to run with an empty rule or no names (exit 2).
* `go-output.txt` and `rust-output.txt`: byte-identical, 28 lines, one per vector, each equal to the `v2` column of the vector file. The gate checks the exact inventory (every vector once; a duplicate, an unknown id, a malformed line or a verdict other than accept/refuse is refused), the equality with the vectors, and the equality of the two outputs; identical outputs alone are no evidence (two outputs that share a defect are byte-identical), which is why the verdicts are compared with the vectors and the vectors are run through the real Python checker (check C2).
* Run (the toolchains were used in containers: Go `go1.26.11`, Rust `rustc 1.99.1`; the Rust example is put in the Forms checkout `cic-primitive-forms` `2f02a75`, which already depends on `regex` and `serde_json`):
  `go run . names.json rule.json` (with `runner.go.txt` as `main.go` in a module that requires nothing), and `cargo run -q --example nameverdict -- names.json rule.json` (with `runner.rs.txt` as `rust/examples/nameverdict.rs`).
* The CI gate does **not** re-run the two runners (it has no Go or Rust toolchain step); it verifies the committed outputs against the vectors and the exported inputs against the real files, and the seeded faults show that an altered output, an altered input, a narrowed rule and a duplicated line each turn the gate red.
