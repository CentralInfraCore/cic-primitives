# Node-name rule: the measurement (not production code)

Evidence for `docs/en/GRAMMAR-NODE-NAME-PROFILE-DESIGN.md` (decision D1, cic-primitives #39). Nothing here changes the grammar, a checker, a pin or a Form.

* **Form behavior on node names** (`gen_cases.py`, `cases/`, `go-output.txt`, `rust-output.txt`, `verification.txt`): 16 cases and 48 documents on the **unchanged** Form (`cic-primitive-forms` `main` `2f02a75592a4b0894a3b76891e9ba3741479a7c5`, grammar profile `cic-primitives-73ae469-6a188078`; Rust `rustc 1.99.1`, Go `go1.26.11`). One schema per name (a single mandatory string field of that name) and documents with the name present, absent and replaced. Result: only the empty name is refused (`SCHEMA_INVALID`); every other name, including the ones the pinned grammar forbids, compiles and is validated by its exact text; case-distinct siblings are distinct fields. The first run **falsified the hypothesis** that every case compiles (the empty name); `gen_cases.py` records the observed refusal as an explicit expectation. The two raw outputs are byte-identical and `verify_measurement.py` (byte-identical to the one of `docs/evidence/forms-capability-measurement/`) accounts for every case and document. The probes `probe.go.txt` and `probe.rs.txt` are those of the earlier measurements (see their README for how to run them); the Rust probe reads only case directories whose name starts with `K`.
* **Regular-expression flavors** (`names.json`, `patterns.json`, `namepat.go.txt`, `namepat.rs.txt`, `namepat-go-output.txt`, `namepat-rust-output.txt`, `name-rule-check.txt`, `name_rule_check.py`): 24 names and 4 patterns (the current rule, two candidates, a line-feed guard) applied by Go (RE2) and the Rust `regex` crate (byte-identical), by Python's `re` (search and fullmatch) and through the JSON Schema library (`jsonschema 4.19.2`, Python 3.14.4). The only flavor difference is a **trailing line feed**; the pinned checker (`check_grammar.py`) accepts `abc\n`. A bounded exhaustive check (length 1 to 5, 10-character alphabet, 111 110 strings) shows that the candidate `^[a-z][a-zA-Z0-9_]*$` only widens the current rule and adds only names with an upper-case letter. `namepat.go.txt` is put as `main.go` in a standard-library-only module (`go run . names.json patterns.json`); `namepat.rs.txt` as `rust/examples/namepat.rs` in the Forms checkout (`cargo run -q --example namepat -- names.json patterns.json`).
* **Fail-closed evidence tool** (`name_rule_check.py`): the two raw regex outputs must contain **exactly** one line `pattern|index|true` or `...|false` for every (pattern, name index) and nothing else: a malformed line, an unknown pattern, an unknown or non-canonical index, a verdict that is not `true` or `false`, a **duplicate** and a missing pair are each refused (the first version used `tab[(p, i)] = (m == "true")`: a duplicate silently overwrote the earlier line and any garbage verdict became `false`). The documented V1 behavior of the pinned checker (`abc` accepted, `createdBy` refused, `abc\n` **accepted**) is **asserted**, not only printed: a change of any of the three fails the check on purpose, so the design document must be revisited. A bounded exhaustive check also asserts that the V1 checker's actual language is the V1 rule plus one line feed after a valid name, and that V2 refuses nothing else the checker accepts.
* **Self-test of the evidence tool** (`selftest_name_rule_check.py`, `selftest-name-rule-check.txt`, 18 checks): the real inputs are accepted; 17 planted defects are refused, each with its own reason, among them ten defects planted **identically in the Go and the Rust output** (a duplicated line, a duplicated line with the opposite verdict, a verdict `maybe`, an empty verdict, an unknown pattern, an unknown index, a non-canonical index, a malformed line, the same pair missing in both, both outputs empty), because two byte-identical broken outputs are no evidence of correctness; a checker that is repaired (`abc\n` refused) and a wrong description of the checker's language are refused too. Measured against the **previous** version of the tool: of seven identically broken output pairs it accepted one (an exact duplicate) and refused the other six only through side effects (an assertion, a derived mismatch), not through a stated input check. An earlier edit helper truncated the file before reading it (a planted defect refused for an accidental reason); it now reads first and refuses a planted edit that changes nothing.
* `SHA256SUMS`: digests of the outputs and the tools. `cases/` is byte-exact (`.gitattributes`).
